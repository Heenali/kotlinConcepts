@Composable functions can be called multiple times. This is because whenever the UI state changes, Compose performs recomposition to update the screen.

If you declare a normal variable inside a composable, it gets initialized again during every recomposition.

Example (Incorrect):

@Composable
fun MyScreen() {
    var text = ""

    TextField(
        value = text,
        onValueChange = {
            text = it
        }
    )
}

Problem:

Every time you type a character, recomposition happens.
The variable text is recreated and initialized with an empty string ("").
As a result, the entered text is lost.
Solution: Remember the State

To preserve the value across recompositions, use remember with mutableStateOf().

@Composable
fun MyScreen() {

    val state = remember {
        mutableStateOf("")
    }

    TextField(
        value = state.value,
        onValueChange = {
            state.value = it
        }
    )
}
How it works
remember stores the state during recomposition.
mutableStateOf("") creates an observable state.
Whenever state.value changes, Compose automatically triggers recomposition.
During recomposition, remember returns the previously stored value instead of creating a new one.

-------------- produceState & derivedStateOf Examples

produceState

produceState is used when you want to convert asynchronous data (API calls, Flow, database data, etc.) into Compose State.

It combines:

remember
mutableStateOf
LaunchedEffect

into a single API.

When the API returns data:

value changes
Compose automatically triggers recomposition
UI updates automatically

derivedStateOf

derivedStateOf is used to create calculated state from other states.

It helps avoid unnecessary recompositions and improves performance.

Use LaunchedEffect for automatic side effects.
Use rememberCoroutineScope() for user-triggered events like button clicks.
remember() survives recomposition but not Activity recreation.
rememberSaveable() survives both recomposition and configuration changes such as screen rotation.
